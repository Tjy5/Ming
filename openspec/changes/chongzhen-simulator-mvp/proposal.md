## Why

明末崇祯朝是中国历史上决策博弈最密集的时期之一——财政崩溃、党争激烈、边患与民变并发。现有的历史模拟游戏要么纯文本聊天缺乏系统性，要么是固定剧本缺乏AI驱动的动态推演。本项目构建一款Web端政局模拟器，让玩家以崇祯视角体验"每一道政令都牵一发动全身"的决策压力，AI实时生成因果叙事和连锁事件。

## What Changes

- 新建完整项目：React前端 + Python FastAPI后端 + SQLite存储
- 实现确定性规则引擎，处理政令→数值变化的因果链
- 实现AI抽象层（多Provider切换：Mock/OpenAI/Claude/Ollama），负责叙事生成与连锁事件
- 构建游戏UI：简化区域地图（8大区）、资源条、派系面板、事件栏、操作区（固定按钮+自由输入）
- 实现操作触发式回合制（每道政令=推进一个月）
- 实现存档/读档系统（SQLite持久化）
- 自由文本输入需AI解析为结构化政令后走规则引擎

## Capabilities

### New Capabilities
- `game-state`: 游戏状态模型——资源（钱粮/人口/军备）、全局指标（民心/军心/朝廷威望）、4派系（东林党/阉党残余/勋贵集团/边将势力）、8区域（京畿/辽东/陕西/江南/中原/山东/云贵/川蜀）
- `rule-engine`: 确定性规则引擎——政令效果查表、派系反应计算、区域影响传导、连锁事件触发检测
- `ai-narrative`: AI叙事层——Provider抽象接口、MockProvider、叙事生成（基于数值delta）、自由输入解析为结构化政令、连锁事件文本生成
- `decree-system`: 政令系统——5~8个固定政令按钮（加税/减税/增兵/裁兵/任免/外交/赈灾/严刑）、自由文本输入框、政令验证与执行流程
- `game-ui`: 游戏界面——简化区域块地图（色块表示稳定度）、顶部资源条、右侧派系面板、下方事件栏、操作区布局
- `save-system`: 存档系统——SQLite存储GameState快照、存档/读档/自动存档、存档列表管理

### Modified Capabilities

（无，全新项目）

## Impact

- 新建前端项目（React + TypeScript + Vite）
- 新建后端项目（Python + FastAPI + SQLite）
- 需要AI API密钥配置（通过环境变量，MockProvider可零配置运行）
