# 调研 04：优点清单（可借鉴项）

- **日期**：2026-08-07
- **说明**：每条标注来源 URL 与「Ming 是否已实现」。已实现判定基于对 `D:\1something\Mingchao\Ming\` 的快速代码勘查（backend/ai/prompts.py、backend/engine/core.py、backend/engine/scripts.py、frontend/src/components/），"待核实"表示需进一步确认细节或未发现对应实现。

## A. 游戏设计维度

### A1. 自然语言作为策略输入（诏书自由撰写）
- **优点**：玩家不点选项、不选 A/B，而是直接写诏书。"玩家不是从固定选项里做选择，而是用自然语言下一道诏书。AI 要判断这道诏书是否符合当前国库、民心、技术条件、官员关系和历史环境，再把结果反写进整个世界状态"。以"相对较低的上手门槛做出极高的自由度与可能性"。
- **来源**：https://www.pingwest.com/a/313764；https://zhuanlan.zhihu.com/p/2042377430527206187
- **Ming 是否已实现**：已实现（EdictWritingPanel.tsx + prompts.py 政令意图解析 + StructuredDecree 结构化政令）

### A2. 固定历史事件锚点 + AI 推演的混合架构
- **优点**：本地解包发现 `DEFAULT_KEY_EVENTS` 硬编码时间表（turn 8 己巳之变/21 明末大鼠疫/65 李自成攻陷北京等），事件触发带 ±2 回合随机偏移。"AI 全自由"背后有历史叙事骨架，既保证史实感又保留自由变化。
- **来源**：chinese-strings.txt L3952-3958、L10003-10004
- **Ming 是否已实现**：已实现（backend/engine/scripts.py 的 ScriptEvent.trigger_year 脚本事件注入系统；engine/core.py inject_script_events）

### A3. 每季度动态时政任务（目标驱动）
- **优点**：每季度根据国家整体情况生成任务，长期不理则"溃于蚁穴"；"玩家的每一次选择都会成为下一轮危机的起点"。
- **来源**：https://www.3dmgame.com/original/3745943.html；https://www.pingwest.com/a/313764
- **Ming 是否已实现**：已实现（MissionPanel.tsx；engine/core.py detect_memorial_triggers/detect_chain_events）

### A4. 官僚执行损耗（政令≠结果）
- **优点**："您的意志必须经过庞大的官僚系统层层传达……政令可能被层层盘剥、被曲解甚至阳奉阴违"——贪腐 90+ 时赈灾银到达百姓手中不足三成。政令的非完美执行是策略深度的来源。
- **来源**：chinese-strings.txt L117-118；https://zhuanlan.zhihu.com/p/2042377430527206187
- **Ming 是否已实现**：待核实（engine 有 apply_base_effects/apply_region_impact 等，但"执行损耗"模拟程度未确认）

### A5. 开局即死局（历史困境的张力）
- **优点**：开局直面国库赤字、陕西大旱、边军欠饷、阉党祸乱等"每一个都会动摇国本"的问题，玩家必须做两难取舍（救陕西=财政崩溃；不救=骂名）。困境塑造代入感与破局成就感。
- **来源**：https://www.3dmgame.com/original/3745943.html；知乎通关长文
- **Ming 是否已实现**：待核实（朱元璋开局定位不同，需对照 Ming 的开局剧本设计）

### A6. 大臣建议沉淀为"诏书建议库"
- **优点**：廷议/对话产出的建议可一键生成总结报告入库，写诏书时侧边栏随时查阅——把对话内容转化为可复用的游戏资源。
- **来源**：chinese-strings.txt L135-136、L4065-4066；https://www.3dmgame.com/original/3745943.html
- **Ming 是否已实现**：待核实

### A7. 结局生成系统（生平/庙号/评分/未来推演）
- **优点**：通关后 AI 生成生平事迹、功过总结、庙号与百年"未来推演"，附穿越评分——长线目标感 + 天然的晒档传播素材。
- **来源**：知乎回答（"穿越评分 98""明烈祖"）https://www.zhihu.com/question/2004918435499501395
- **Ming 是否已实现**：已实现（GameOverScreen.tsx，细节待核实）

## B. AI 交互维度

### B1. 圣旨总结思维链 prompt（防长上下文串题）
- **优点**：触发"朕准奏，爱卿拟旨"时，prompt 显式要求：只总结本回合最新主题、对过去讨论"适量遗忘"、200 字以内、皇帝第一人称书面白话、不输出思考过程。针对 AI 文游最大的"记忆串题"痛点做了工程化克制。
- **来源**：chinese-strings.txt L3969-3980（全文见 02-玩法与系统设计.md）
- **Ming 是否已实现**：待核实（prompts.py 未发现对应"圣旨总结/适量遗忘"prompt）

### B2. 大臣 Agent 化 + 扮演 prompt + 多维属性
- **优点**：每个大臣是独立 Agent（`prompt`: "为Agent扮演大臣的提示词"），带军事/管理/知识/政治能力+腐败/忠诚/野心/势力八维属性；廷议时按派系立场给差异化建议（阉党卖官鬻爵 vs 东林党彻查盐引），立场鲜明可博弈。
- **来源**：chinese-strings.txt L7555-7614；https://www.3dmgame.com/original/3745943.html
- **Ming 是否已实现**：部分已实现（MinisterDialogue.tsx/CourtAssemblyView.tsx/positions.py），但大臣是否带独立扮演 prompt 与八维属性**待核实**

### B3. 三层架构：状态约束/意图判断/状态保留
- **优点**："模型输出须符合历史+当前数据（初始状态约束）→ 判断玩家意图（整活判定）→ 推演故事转化为结构化数据入库（状态保留）"。回合制下"不直接驳回，一部分实现、做到一半"。给自由但不失控的关键工程方案。
- **来源**：https://www.pingwest.com/a/313764
- **Ming 是否已实现**：部分已实现（check_preconditions/StructuredDecree/validate_target 类似约束层），意图判断层与状态保留层细节**待核实**

### B4. 步进式状态机（回合增量状态）
- **优点**："每个回合就是一个状态，只需要保存前一个状态，进行增量或修改"；配合记忆压缩、特殊内容反复提取强化。稳定性和成本的双赢方案。
- **来源**：https://www.pingwest.com/a/313764
- **Ming 是否已实现**：待核实（backend/db/saves.py + GameState，机制细节需对照）

### B5. 数值区间概念框 + 硬性事件触发
- **优点**：模型只理解"10-20 / 20-50 是一个概念"，配合硬性框架（民心归零→系统提醒大模型"该报叛军了"）——AI 生成与确定性规则的混合控制。
- **来源**：https://www.pingwest.com/a/313764
- **Ming 是否已实现**：待核实（engine 有 check_preconditions/assign_urgency，概念框提示方式未确认）

### B6. 对话式科技/项目推进
- **优点**：科技研究是可持续对话推演的过程（蒸汽机卡"密封问题"→派 AI 去南洋找橡胶→成功），而非一锤子数值。玩家实测"让AI到南洋找橡胶最后还是成功了"。
- **来源**：知乎回答（清华玩家档）https://www.zhihu.com/question/2004918435499501395
- **Ming 是否已实现**：待核实

### B7. benchmark 质量保障（成功率 99%）
- **优点**：自建 benchmark 跑 100 次验证世界状态修改成功率（要求 99%+），模型判断+程序化判断双轨；专家模式达到 98.7% 推演前提正确率、99.86% Function Call 匹配率。AI 游戏的可靠性工程标准。
- **来源**：https://www.pingwest.com/a/313764；https://zhuanlan.zhihu.com/p/2042377430527206187
- **Ming 是否已实现**：待核实（存在 test_result.txt，但未发现 benchmark 框架）

### B8. 拒绝 RAG、全局势上下文
- **优点**：制作人明确放弃 RAG——"玩家提到什么，它才容易关注什么"导致陕西民变被忽略。用步进状态机+全量局势上下文替代检索式记忆。
- **来源**：https://www.pingwest.com/a/313764
- **Ming 是否已实现**：待核实

## C. 数值系统维度

### C1. 国策 = 硬编码数值效果 + 提示词注入双轨
- **优点**：国策数据结构含 `current_turn_effect`（"一次性改变数值的硬编码"）、`context_text`（拼接入下回合的提示词）、`long_term_prompt`（长期修正提示词）、`db_modify`/`kb_modify`——确定性与 LLM 生成精确分工。
- **来源**：chinese-strings.txt L9747-9785
- **Ming 是否已实现**：待核实（StructuredDecree 有硬编码效果，long_term_prompt 注入未确认）

### C2. 通货供应量等"系统性"经济设计
- **优点**：明确模拟"大明长期通货紧缩、银根紧缺"，玩家需设法增加供应量激活商业与税收——数值系统承载历史叙事（货币史机制直接变成玩法）。
- **来源**：chinese-strings.txt L76（界面指引手册）
- **Ming 是否已实现**：待核实

### C3. 派系/阶层双轨满意度
- **优点**：派系（阉党/东林党影响力对比）+ 阶层（军人/宗亲/士绅/农民/官僚/宦官诉求）双轨监控，政策按群体利益产生不同反馈（触动士绅→税收暴跌）。
- **来源**：chinese-strings.txt L90-93；https://zhuanlan.zhihu.com/p/2042377430527206187
- **Ming 是否已实现**：已实现（FactionPanel.tsx；engine/core.py apply_faction_reactions）

## D. UI 与叙事维度

### D1. 地图即操作平台 + 顶部数据栏 + 侧边栏
- **优点**：点省份下地方诏书、点军队看士气补给、右键调兵；六项核心数值常驻顶部（悬停看构成）；右侧管理内阁/派系/阶层/军队。信息架构清晰，且每页有配套"游戏界面指引手册"（直接作为 prompt 注入 AI 的世界规则文档）。
- **来源**：chinese-strings.txt L63-105；https://www.3dmgame.com/original/3745943.html
- **Ming 是否已实现**：已实现（RegionMap.tsx/ResourceBar.tsx/EventBar.tsx 等）

### D2. 司礼监润色（仪式感包装）
- **优点**：白话诏书一键润色为"符合大明礼制、文字韵味十足"的文言诏书——AI 同时服务玩法与氛围。
- **来源**：chinese-strings.txt L144-149
- **Ming 是否已实现**：待核实

### D3. 奏疏作为主要信息流
- **优点**："奏疏=上一回合诏书执行结果+突发历史事件+紧急汇报"，官方将其定位为"获取情报的主要来源，务必每回合仔细审阅"——信息密度与叙事包装兼备。
- **来源**：chinese-strings.txt L98-100
- **Ming 是否已实现**：已实现（MemorialPanel.tsx；detect_memorial_triggers）

## E. 商业模式维度

- **来源**：https://zhuanlan.zhihu.com/p/2042377430527206187；https://www.pingwest.com/a/313764

### E2. 开放自定义 API 与创意工坊（生态路线图）
